Engineering Architecture & Deployment Catalog

Technical reference for running X Desktop, deploying local neural translation models on GPU, and managing dual-engine translations on Linux and Windows.

01. System Architecture

X Desktop is a standalone client engineered to decouple X browsing from your daily browser instance, enforcing complete profile isolation while integrating native OS capabilities:

Isolated Profile Storage

Cookies, LocalStorage, and Cache are strictly contained in ~/.config/x-desktop on Linux and %APPDATA%\x-desktop on Windows. Zero credential leakage with Chrome, Brave, or Edge.

Dual-Engine Neural Pipeline

Default local fallback delivers sub-80ms human-grade translations. GPU acceleration offloads deep technical/CS reasoning to local GGUF models on NVIDIA RTX hardware.

02. Local Model Catalog & GGUF Deployment

The desktop engine interfaces with standalone GGUF quantized models executed through an isolated local runtime process on port 28491.

Model Format / Quant Size Context Primary Use Case
Gemma 4 (E2B-it) Q4_K_M.gguf 2.9 GB 12,288 Deep technical CS, AI jargon, idioms, multi-line formatting
Qwen3-VL (2B-Instruct) Q4_K_M.gguf 1.03 GB 8,192 Multimodal Vision OCR and compact resource environments
Deployment File Paths:

Place the GGUF weights in the following operating system directory:

Linux:   ~/.local/share/x-desktop/models/gemma-4-E2B-it-Q4_K_M.gguf
Windows: %USERPROFILE%\.local\share\x-desktop\models\gemma-4-E2B-it-Q4_K_M.gguf

03. GPU Acceleration (Vulkan & CUDA)

X Desktop executes models directly against your discrete GPU (NVIDIA RTX 4060 or compatible) to sustain 85+ tokens per second:

# Automated Runtime Launch Parameters:
llama-server   --model ~/.local/share/x-desktop/models/gemma-4-E2B-it-Q4_K_M.gguf   --port 28491   --host 127.0.0.1   -ngl 99   -fa on   -c 12288   -t 6   -np 1   --reasoning off   --reasoning-budget 0   --log-disable

The runtime automatically binds to libggml-vulkan.so on Linux and vulkan-1.dll on Windows, ensuring complete layer offloading with ~2.7 GB VRAM footprint.

05. Google Authentication & Session Bridge

Google blocks embedded Electron webviews with security error Couldn't sign you in - This browser or app may not be secure. X Desktop resolves this via the native Session Bridge:

  1. Click Sign in with Google or open Session Assistant from the context menu.
  2. Authentication opens securely in your default desktop browser (Chrome, Brave, or Edge).
  3. Copy your auth_token cookie value and paste it into the Session Assistant.
  4. The client injects the token via session.defaultSession.cookies.set() with Secure and HttpOnly flags, establishing a permanent isolated session.
