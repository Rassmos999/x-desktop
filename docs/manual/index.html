X Desktop Manual

Everything needed to install the client, give it a model, translate posts, and recover when something is not ready. Commands are copy-ready, paths are exact, and every capability described here is implemented in the published source.

01Installation

Installation

Choose the package for your system. Each one installs the application, the desktop entry, the icon set, and a x-desktop launcher on your PATH. None of them install a model; that is a separate step, covered in Models.

Download links for each platform
SystemPackageInstall command
Debian, Ubuntu .deb sudo apt install ./x-desktop_1.0.1_amd64.deb
Fedora, RHEL .rpm sudo dnf install ./x-desktop-1.0.1-1.x86_64.rpm
Arch Linux .pkg.tar.zst sudo pacman -U x-desktop-1.0.1-1-x86_64.pkg.tar.zst
Windows x64 portable .zip Extract, then run x-desktop.exe. install-shortcut.bat adds a desktop shortcut.

All four are attached to the latest release:

Release downloads
https://github.com/Rassmos999/x-desktop/releases/latest

From source

Building needs Node.js 20 or newer, Python 3, make, and either ImageMagick or librsvg for icon generation.

Build and install for the current user
git clone https://github.com/Rassmos999/x-desktop.git
cd x-desktop
npm install
make icons
make install      # installs to ~/.local; use PREFIX=/usr with sudo for a system install
x-desktop

Uninstall

Remove the application files
make uninstall                                 # source install
sudo apt remove x-desktop                      # Debian, Ubuntu
sudo dnf remove x-desktop                       # Fedora, RHEL
sudo pacman -R x-desktop                        # Arch Linux

Removing the application leaves your profile and models in place. See Data and removal to delete those too.

02First run

First run and sign-in

Launch X Desktop from your application menu or by running x-desktop. The first window loads x.com in a profile created solely for this application, so an existing browser session is neither used nor modified.

Sign in with your X account as usual. If you sign in with Google or Apple, the client routes that step to your system browser, because those providers refuse to authenticate inside embedded views.

Session Assistant

If a browser sign-in cannot complete the embedded session, use the Session Assistant to import the session token directly. Open it from the tray menu or by right-clicking anywhere and choosing Session Assistant.

  1. Sign in to X in a normal browser window.
  2. Open the browser's developer tools, find the auth_token cookie for x.com, and copy its value. Pasting the whole cookie string also works — the client extracts the token.
  3. Paste it into the Session Assistant and apply. The token is written to the isolated session and the window reloads signed in.
Treat it as a password

The auth_token grants full access to your account. Never paste it into a site you do not control, and sign out of X if you believe it was exposed.

03Models

Models

The AI engine is a local model server. It needs two things: the runtime binary, and at least one model file. Both live outside the application directory so they survive updates.

WhatLinuxWindows
Models ~/.local/share/x-desktop/models/ %USERPROFILE%\.local\share\x-desktop\models\
Runtime ~/.local/share/x-desktop/bin/ %USERPROFILE%\.local\share\x-desktop\bin\
Active-model setting config.json, in the folder above models/

Automatic setup

The setup script installs the llama.cpp Vulkan runtime, downloads the required Gemma model, and places both in the folders above. Run it once after installing the client:

Linux · downloads about 3 GB
./tools/setup-ai-engine.sh

On Windows, download the runtime archive and the model file into the two folders shown above:

Windows · runtime
https://github.com/ggml-org/llama.cpp/releases/download/b10828/llama-b10828-bin-win-vulkan-x64.zip

Model files

The engine loads one model at a time. Gemma is required for the AI engine; the vision pair is optional and only adds translation of text inside images.

FileSizePurpose
gemma-4-E2B-it-Q4_K_M.gguf 2.89 GB Required. The text translation model.
Qwen3VL-2B-Instruct-Q4_K_M.gguf 1.03 GB Optional. Vision model for text inside images.
mmproj-Qwen3VL-2B-Instruct-Q8_0.gguf 425 MB Optional. The projector the vision model needs. A projector alone does nothing.
Linux · fetch each file directly
M="$HOME/.local/share/x-desktop/models"; mkdir -p "$M"; cd "$M"

curl -L -O https://huggingface.co/unsloth/gemma-4-E2B-it-GGUF/resolve/main/gemma-4-E2B-it-Q4_K_M.gguf

# optional vision pair
curl -L -O https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct-GGUF/resolve/main/Qwen3VL-2B-Instruct-Q4_K_M.gguf
curl -L -O https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct-GGUF/resolve/main/mmproj-Qwen3VL-2B-Instruct-Q8_0.gguf
How vision is decided

Image translation is offered only when the active model is vision-capable and a projector file is present. If either is missing, the client does not show the translate action on images rather than offering something that cannot answer.

Adding your own model

Any GGUF text model placed in the models folder is listed in the dashboard and can be selected there. Names are matched, not magic: a file whose name begins with mmproj is treated as a projector and is never loaded as a model, and a file is treated as vision-capable when its name contains a recognised vision family such as Qwen…VL.

Two limits apply. The engine loads exactly one file at a time, and the context window is configured at 12,288 tokens, so a model that cannot hold that much will be clamped or refuse to load. Larger models also consume proportionally more VRAM.

Switching takes a few seconds

Changing the active model releases the GPU memory holding the current one and loads the new one, which takes roughly two to five seconds on the reference hardware. The dashboard reports this as a switching state; it is not a freeze.

04Dashboard

Dashboard

The engine dashboard runs at http://127.0.0.1:28492. Open it with Ctrl + Shift + D, from the tray menu, or by right-clicking and choosing AI Telemetry Dashboard.

What it reports

  • Engine state: ready, starting, switching, or offline, with the label spelling out which.
  • VRAM and temperature: read from the GPU, not estimated.
  • Throughput: tokens per second, taken from real inference. It reads -- until a translation has actually been measured.
  • Context allocation: system, input and output tokens against the 12,288-token window.
  • Operations log: the last translations, each tagged with the engine that produced it.

Model panel

The model panel lists every model file in the folder, marks the active one, names the dashboard path, and switches between them. تبديل الموديل / Switch model restarts the engine on the selected file and reports how long it took; Open folder reveals the models directory in your file manager.

Test console

Paste text and run it through either engine. The response includes the round-trip time and the answer, so a claim about translation quality can be checked before you rely on it in the timeline.

05Translation

Translation

There are two engines and they are not equivalent. Knowing which one is answering is the point.

AspectAI engineFast engine
Runs where On your GPU, served from 127.0.0.1:28491 Cloud request to translate.googleapis.com
Needs a model Yes No
Text leaves your machine No Yes
Typical use Technical or idiomatic text where wording matters Getting the gist immediately, or working without a GPU
Read this before relying on privacy wording

The AI engine keeps text on your machine. The Fast engine does not — it sends the text to Google. The client also falls back to the cloud path when the local model returns nothing usable, so a request you started on the AI engine can still complete over the network. The dashboard tags each result in the operations log with the engine that produced it, which is the reliable way to tell which path ran.

Translating a post

  • Whole post: use the translate action beneath the post text. The result appears in place, with a control to restore the original.
  • A phrase: select the text and use the floating tooltip to translate, copy, or replace it inline.
  • Switch engine: the tooltip and the inline action both let you re-run the same text on the other engine.
  • Text inside an image: appears as a translate action on the photo, and only when a vision model and its projector are both installed.

06Filtering

Timeline filtering

Promoted posts, boosted entries, and subscription banners are removed from the timeline before they are drawn, and requests to known advertising and analytics endpoints are blocked at the network layer. The block list covers Twitter and X advertising endpoints, Google ad services, and DoubleClick.

Because filtering happens on requests rather than on finished markup, it removes the promoted entries themselves without affecting video or image loading from the same timeline.

Deleting the profile signs you out and clears the isolated session. Deleting the models folder frees roughly 3 to 4.5 GB depending on which models you downloaded; the next launch simply finds no model and says so.

09Troubleshooting

Troubleshooting

The dashboard says the engine is offline

Nothing is answering on port 28491. Check three things in order: a model file exists in the models folder, the llama-server binary exists in the runtime folder, and no other process is holding the port.

Linux · check what the engine is doing
ls -la ~/.local/share/x-desktop/models/ ~/.local/share/x-desktop/bin/llama-server
curl -s http://127.0.0.1:28491/health
ss -ltnp | grep 28491

Start it by hand to see the engine's own error, which the client discards when running detached:

Linux · run the engine in the foreground
~/.local/share/x-desktop/bin/llama-server \
  --model ~/.local/share/x-desktop/models/gemma-4-E2B-it-Q4_K_M.gguf \
  --port 28491 --host 127.0.0.1 -ngl 99 -fa on -c 12288

Translation returns nothing, or the wrong engine answers

Confirm the model is loaded by watching the AI engine, not the Fast one, in the dashboard test console. When the local model produces nothing usable the client completes the request through the cloud path, so a successful result does not by itself prove the local engine answered — the operations log shows which engine it was.

Switching a model appears to hang

It is reallocating GPU memory. The dashboard shows a switching state, and the switch reports its duration when it completes. If it fails instead, the panel names the reason and keeps the previous model selected. A switch that exceeds its timeout is reported as a failure rather than waiting indefinitely.

Google sign-in is refused

Google blocks embedded views. The client detects that and opens your system browser instead, then imports the session through the Session Assistant. If the import does not stick, the token has most likely expired — repeat the import with a freshly copied value.

Wayland window rules

The release includes example rules for Niri and Hyprland under usr/share/doc/x-desktop/. They are examples, not requirements: copy the ones you want into your own configuration.

GPU memory is still held after closing the window

Closing the window keeps the application in the tray, and the engine keeps its model loaded so the next translation is immediate. Use Ctrl + Q or the tray's Quit action to stop the engine and release the memory.

10Advanced

Advanced reference

How the engine is actually launched, for readers who intend to tune it. The client starts the server with these arguments; the same command can be run by hand for diagnosis.

ArgumentMeaning
--modelThe active model file, resolved from config.json
--port / --hostLocal server on 127.0.0.1:28491
-ngl 99Offload all layers to the GPU
-fa onFlash attention
-c 12288Context window in tokens
-t 6CPU threads used alongside the GPU
-np 1A single parallel slot; text and vision use separate slot ids
--mmprojAttached only when the active model is vision-capable and the projector exists

Runtime

The engine is a llama.cpp server build, b10828, compiled with the Vulkan backend. It carries its own shared libraries in the runtime folder, which is why the client sets the library path before launching it rather than relying on system packages. The archive is llama-b10828-bin-ubuntu-vulkan-x64.tar.gz on Linux and llama-b10828-bin-win-vulkan-x64.zip on Windows.

Endpoints

The dashboard and engine expose a small local HTTP surface, bound to the loopback interface only.

EndpointPortPurpose
GET /api/telemetry28492Engine state, model, VRAM, throughput, history
GET /api/models28492Installed models, active model, vision availability
POST /api/models/active28492Switch the active model and restart the engine
POST /api/models/reveal28492Open the models folder in the file manager
POST /api/translate28492Translate text through either engine
POST /api/translate-image28492Translate text found in an image
GET /health28491Engine liveness, used by the client

The model endpoints change state, so they accept requests only from this machine's own dashboard origin. Read-only endpoints and the translation endpoints are unaffected.
